§2 · slide 2a · agent/dataagentbench.svg · the fig-agent, drawn as the Agent tab draws v8

2aOne Opus session, three tools, one statement — the whole agent

Figure · the v8 agent system: question → Agent SDK → mcp dab → three tools → Postgres → validator

  • Session: Agent SDK claude child · Opus 5.5 medium · ≤ 30 turns · 900 s · empty directory, no built-in tools
  • Prompt: system.md 7.6 k (the playbook) + tables map + this dataset's notes ~1.7 k + description + hints ≈ 18 k for crmarenapro; the question alone as the user message
  • Tools: query_db, describe_table as dab_agent; submit_answer(sql, mode, plan) re-runs the SQL, so the result is known exactly
  • Versus the board: one prompt per dataset, no per-question text or tool; #1 ships five prompt variants, #2 per-question operators

Small on purpose: a version differs from its parent in one file and twelve notes, so every gain is a diff.

§3 · slide 3a · loop/dataagentbench.svg · the fig-loop, drawn as the Optimise tab draws a round

3aOne round: read every miss, write one prompt, pass four guards, promote on Pass@1

Figure · round 5 (v6 → v8) on the seven stages, with the round's own counts

  • Read: 20 misses — 16 failed statements, ledgered by step (sources 5, parse 5, shape 4, rank 1, filter 1), and 4 wrong answers
  • Write: 13 Opus sessions (3 per break step, 10 per dataset), 28 writes; the guards refused 19, kept 9
  • Ship: 3 playbook sections + 6 notes → v8; 54 trials; 48/54, Pass@1 0.904; promoted under D46
  • Learns from: the golden diffs and each question's history in MLflow; never a gold value, never a question named

The optimiser is an agent with a pen; what it may read and write is the design.

As the Optimise tab draws it (frontend/src/pages/Optimise.tsx, /optimise/v8_sql) · agents/v8_sql/optimise.json · eval/rounds.py · eval/guards.py

§3 · slide 3b · chart/dataagentbench-coverage.svg · the data and the golden set

3b54 questions over 12 datasets, and a golden statement for 49 of them

Figure · the benchmark's data and the golden SQL coverage, one cell per question

  • The data: 12 datasets, 4 engines upstream, 8.4 GB → one Postgres schema, 2,811 tables
  • Coverage: 49 of 54 — 36 exact, 8 pass but differ from the gold text, 5 evidence; 5 none
  • By hand: each run as the agent's role, judged by the question's validator, saved by a person
  • agnews has none: its category lives in no column

A golden is proof the question is answerable in one statement over the loaded data.
