00 · verdict

Three things the page has to say now

The story is now 73% → 90.5%, in four causes

v1 73.0% → v2 77.1% (GEPA) → v8 81.7% (campaign c01, retriever) → sdk_v1 90.5% (v8's four prompts distilled into one Claude session). Each step has a named cause and a gate row. The case study opens on this chart, as asked.

Kept honest in the same slide: the SDK step changed model and architecture together, and 90.5% is on a split drawn from the public train pool — so "one session beats four agents" is not established; a win at equal optimisation effort is.

The gate got strictly harder, and it un-promoted three versions

Net-positive with p "recorded" is retired. The campaign rule is net positive and one-sided, cluster-corrected McNemar p < 0.05 (clusters = conversations). Re-judged under it, v3_1, v4 and v5 were all rolled back to v2 on 2026-09-03; v8 is the first promotion that passed.

That rollback is the eval-loop deep page's best paragraph: the evidence "was never wrong, it was never sufficient".

The SDK won, on a prompt the pipeline's loop wrote

sdk_v1 was distilled from v8 — three campaigns and seven experiments of DeepSeek optimisation. The SDK loop's own attempt to improve it (sdk_v2) was rejected at −2.9 pp, and the loop is starving at 90% (≈34 first-wrong cases per 100 reports).

It promotes to sdk_champion only, never champion; serving is unchanged. The SDK deep page carries the confound, the contamination note and the Haiku swap.

From 73% to 90.5%, in four named causes

Each bar is one registry event. v2 came from a GEPA run over DSPy. v8 came from the eval loop: a teacher blamed the retriever, one prompt changed, and a significance gate promoted it on 349 unseen questions. sdk_v1 is those four prompts distilled into one Claude session.

↳ go deep: the loop · the runtime test

§3 · slide 6

Nine verdicts, two promotions, all on the same 349 questions

The rule since 2026-09-03: net positive on the shared gate questions and one-sided, cluster-corrected McNemar p < 0.05, clustered by conversation because a wrong turn poisons the turns below it. Seven challengers moved the number and were refused; v8 and sdk_v1 cleared the bar.

Re-judged under this rule, v3_1, v4 and v5 were rolled back to v2 the same day. v5's p was 0.207 with a CI of [−3.2, +7.6] that contains zero.

↳ go deep: the loop's setup, every command, the cycle log

§3 · slide 7

The whole gain is on the reasoning turns

Number turns are a lookup and both runtimes already get 95.5%. Program turns need a plan, retrieval and arithmetic across the conversation: the single session lifted them 75.2% → 88.2%, 35 fixed against 4 broken. Program-match stayed at 41%: it reaches the right numbers without reproducing the gold programs.

Swapping the model under the same prompt cost 3.2 pp (Haiku 4.5, 87.4%, p 0.051, not significant) and saved $10 a pass.

↳ go deep: the runtime test, both arms, every SDK experiment
